# 美团配送设置 · Ego Lite

查看和调整美团闪购门店的起送价、基础配送费，也可以开启或关闭门店已有的手动时段，例如下雨时段。

## 安装

1. 从仓库下载或克隆完整项目。
2. 安装 [Node.js](https://nodejs.org/) 20 或更高版本，以及 [Ego Lite](https://lite.ego.app/)。打开 Ego Lite 完成首次设置，再打开一个新终端。
3. 在项目目录运行下面三个命令。前两个能显示版本、第三个能列出 Ego 资料，就可以登记门店。当前实测环境为 Windows、Node.js 24 和 Ego Lite 0.6.2.7。

   ```text
   node --version
   ego-browser --version
   node cli.mjs profiles
   ```

4. 如果从对话操作，按所用工具的 Skill 安装方式添加**整个项目目录**，然后开始登记。只复制 `SKILL.md` 会缺少执行脚本。也可以直接在终端使用下方命令。

若终端找不到 `ego-browser`，回到 Ego Lite 完成首次设置，然后重新打开终端。

### Windows 安装中断

下载后运行安装器，按图形向导完成安装，再打开 Ego Lite。实测安装器使用 `/S` 会返回退出码 1。如果由工具启动安装窗口，且窗口随命令结束消失，可在保持运行的后台任务中使用 PowerShell 的 `Start-Process -Wait`。等你在窗口完成向导后，再继续下面的步骤。

## 首次登记门店

每家店需要门店全名、美团门店 ID 和所属中台。如果所有门店都属于同一个中台，中台名写一次就行。工具会保存名单，按实际中台数准备登录。

从对话开始，可以直接发下面这句，把示例换成自己的门店。

> 登记美团闪购门店「示例商店（甲店）」，门店 ID 90000001，属于示例中台甲。先核对这家店有哪些时段、档位和开关，保存到本地。

一个中台用一个 Ego 资料。已有资料可以复用，缺少资料时在 Ego 里用中台名新建。工具会打开对应的美团登录页，你在页面上选择登录方式。完成后回复「登录完成」。如果有两个中台，可以先回复「某某中台已登录」，工具会先核对这个中台的门店。已登录的中台直接开始核对。

从终端操作时，把 [门店示例](examples/stores.example.json) 复制为 `.local/stores.json`，填入门店和 `profiles` 显示的资料 ID。门店 ID 用字符串，门店名按美团显示填写。用 `platforms` 里登记的中台键启动引导，例如示例中的 `demo`。

```text
node cli.mjs onboard demo
```

如果返回 `login_required`，在打开的 Ego 窗口登录后，把返回的空间 ID 加在命令末尾，例如 `node cli.mjs onboard demo 42`。工具按名单读取时段、档位、起送价、配送费和开关，结果保存在 `.local/store-profiles/`。想单独核对一家店，可以用 `node cli.mjs inspect 90000001`。

## 日常调整

在对话里说清门店、时段、档位和目标。例如：

> 把示例商店（甲店）的正常时段全部档位起送价改成 16 元，普通第 1 档的基础配送费改成 3.50 元。

也可以用 [单店示例](examples/job.example.json) 或 [批量示例](examples/batch.example.json) 填写任务，存在自己的 `.local/` 下，再用下面的命令执行。

```text
node cli.mjs apply 90000001 .local/job.json
node cli.mjs batch .local/batch.json
```

| 要做的事 | 任务怎么写 |
| --- | --- |
| 调整一个时段 | `title` 填只读核对时看到的时段名。重名时填完整标题。 |
| 调整该时段全部档位 | `minOrder` 或 `baseFee` 直接填金额字符串，如 `"16.00"`。全部范围包含快送。 |
| 调整一个或多个档位 | 用数组逐条填 `range` 和 `value`。普通档可用 `ordinaryTier`，也可用原名、距离和页面序号定位。 |
| 开启或关闭特殊时段 | `"enabled": true` 开启，`"enabled": false` 关闭。美团要求选自动关闭时间时，用 `activeMinutes` 填页面提供的选项。当前支持 30 或 60 分钟。 |

任务里只填写本次要改的内容。要改多个时段，就在 `periods` 中逐个列出。同一任务既改价又开启特殊时段时，价格保存并核对后再开。普通档位和快送的区别见 [档位与时段](docs/档位与时段.md)。

普通提示和本次操作的保存确认会自动处理。遇到其他弹窗时，先看正文和按钮，再决定如何继续。登录、验证码或需要你选定新目标时，才会请你操作。

批量任务中，同一 Ego 资料或同一美团账号的门店逐家执行。Ego 资料和账号都不同的门店可以同时执行。任务运行时，请避免在同一 Ego 资料里手动切店，切店可能改变脚本正在读的价格。

## 核对结果和恢复原价

每次操作都会把现场原值、保存反馈和重新打开后的实际读数写入 `.local/runs/`。单店看 `summary.json`，批量看 `batch-summary.json`。

- `verified` 表示实际设置与任务目标一致。原值已经符合目标时会跳过保存。
- `needs_check` 表示需要查看现场。先用 `inspect` 核对实际值，再决定是否继续。
- `login_required` 表示要先在 Ego 登录。登录后可用返回的空间 ID 继续对应门店。

需要恢复原价时，用原任务的记录填写 [恢复示例](examples/restore.example.json)。`from` 填上次调后的值，`value` 填当时的原值。若现场价格后来又变过，脚本会提示核对。

真实门店清单、建档结果和操作记录都放在 `.local/`，请留在自己的电脑上。
